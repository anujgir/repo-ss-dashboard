A dashboard for syllabus coverage, teacher participation, school adoption, and district-to-block performance. Teacher requests indicate participation. Principal approval establishes completion.

01 / Scope

Use the existing .NET Framework 4.7.2 ASP.NET MVC application with Razor, normal HTML, local Bootstrap, CSS, and necessary vanilla JavaScript. SQL Server will supply live metrics in the next implementation step.

Step 1 / design only

Create a new controller with only an Index action returning the dashboard view. No queries, connection strings, approval writes, backend calculations, authentication implementation, or real-data binding in this step. All figures are labeled sample data.

The UI must look complete enough to review: colored summary cards, a responsive sidebar, filters, paired target/achievement charts, an accessible block drilldown, teacher participation, approval summary, and a district reporting table.

05 / Dashboard design and interaction

A navy sidebar frames a light, spacious workspace. Teal represents achievement, violet represents targets, and amber highlights gaps. Cards show text and numbers in addition to color. A persistent sample-data notice identifies the prototype.

Filters: academic year, syllabus month, class, subject, school cohort, and district. The prototype supports 2026-27; later years must come from live data. Apply and reset update all visible sample aggregates. Missing targets or zero denominators must show N/A in the production dashboard.

District names are keyboard-operable buttons. The block section announces selection and can be closed. Charts include numeric labels and a table alternative. Mobile users can open and dismiss the sidebar. CSV export includes only currently displayed sample district results.

06 / Reporting rules

Use the academic-year boundary 2026-04-01 inclusive to 2027-04-01 exclusive. January, February, and March use calendar year 2027. Syllabus month is different from request month and approval month.

Percentage basis / owner confirmation required

For design consistency, sample achieved percentage uses approved monthly topics divided by eligible monthly topics. Sample target values use the same monthly basis. Live TargetPercentage semantics must be confirmed before implementation: monthly completion, monthly contribution to annual syllabus, or cumulative annual progress.

Aggregate with topic-weighted numerators and denominators, not an average of percentages. Deduplicate completed school-topic pairs. Do not sum repeated YearTopics across monthly rows. Join targets at their full class/subject/year/month/cohort key. Only eligible school-class pairs should contribute to denominators.

IsCompleted = 0 alone does not distinguish pending from rejected. ApprovalStatus codes must be supplied before calculating live approval distributions. SOE values, null handling, and stale summary behavior also require explicit definitions.

07 / Delivery and acceptance

  • PRD is saved before dashboard implementation and browser opening is attempted.
  • All six agents read the domain contract and respect the Step 1 boundary.
  • /SplitSyllabus/Index renders through a new MVC controller that only returns its view.
  • Both cohort cards show target and achieved; all five participation counts are visible.
  • District chart shows all 24 sample district names at the default scope; any selected name opens its block chart below.
  • Filters, reset, sidebar, chart labels, table sorting, search, CSV export, and empty states operate on sample data.
  • Local Bootstrap/CSS/JavaScript load without external CDNs. Debug and Release builds include Razor compilation.
  • No database connections, SQL operations, or approval changes are introduced.

08 / Decisions for live implementation

  1. Exact SOE StateSpecificType value and handling of non-SOE/null values.
  2. Meaning of TargetPercentage and comparable achievement denominator.
  3. Column types, keys, academic-year ID, and ClassId/batchId mapping.
  4. Teacher-school assignment source and eligible teacher population.
  5. ApprovalStatus codes, duplicate requests, rejections, and reopening rules.
  6. Summary uniqueness, refresh cadence, and reconciliation with tracking.
  7. Block ID uniqueness, geography permissions, and dashboard audience.

District names for the illustrative geography are based on the Government of Jharkhand district list. All counts, percentages, school populations, and block-level examples remain fictional.
